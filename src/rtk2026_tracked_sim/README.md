# Гусеничная модель RTK2026

Пакет содержит только отдельные SDF и Xacro модели для Gazebo Harmonic.
Единственной точкой запуска симуляции остаётся
`rtk2026_bringup/sim_slam_launch.py`: вид ходовой части выбирается его
аргументом `robot_model`.

## Геометрия

| Параметр | Значение |
|---|---:|
| Корпус | 300 × 180 × 113 мм |
| Расстояние между средними плоскостями бортов | 210 мм |
| Ширина одного борта | 30 мм |
| Радиус переднего и заднего закругления | 60 мм |
| Полная длина опорного контура | 360 мм |
| Полная ширина робота | 240 мм |

Корпус, положение `base_footprint` и сенсоры совпадают с текущей
дифференциальной моделью. Гусеница представлена центральной контактной
полосой и двумя круглыми носками. Это позволяет проверять заезд на балки
высотой 25 мм, но не моделирует отдельные траки, натяжение и грунтозацепы.

`base_footprint` находится на опорной поверхности под осью привода. В Xacro
это корневой пустой link, от которого `base_link` смещён на
`-0.060 0 0.080`. В физическом SDF `base_footprint` является canonical link
и началом координат всей модели.

Links `left_track` и `right_track` закреплены fixed joints намеренно.
`TrackController` двигает контактную поверхность гусеницы, поэтому видимые
цилиндры не вращаются.

## ROS-интерфейсы

- `/cmd_vel` — `geometry_msgs/msg/TwistStamped`;
- `/wheel/odom` — расчётная одометрия по заданным скоростям гусениц;
- `/odometry/filtered` — одометрия EKF;
- `/ground_truth/odom` — поза из физического движка только для диагностики;
- `/scan` — лидар;
- `/imu/data` — IMU;
- `/camera/color/image_raw` и `/camera/color/camera_info` — цвет D435i;
- `/camera/aligned_depth_to_color/image_raw` — совмещённая глубина D435i;
- `/camera/depth/color/points` — облако точек D435i;
- `/camera/imu/sample` — встроенная IMU D435i.

Gazebo TF намеренно не передаётся в ROS. Трансформацию
`odom -> base_footprint` публикует только EKF.

EKF получает продольную скорость из `/wheel/odom` и угловую скорость из
`/imu/data`. `/ground_truth/odom` используется только для проверки и
калибровки.

## Запуск

```bash
ros2 launch rtk2026_bringup sim_slam_launch.py \
  spawn_y:=0.5725
```

Гусеничная модель используется по умолчанию, поэтому
`robot_model:=tracked` можно не писать. Координата `y=0.5725` направляет
робот на блок из 12 электродных балок.

Для проверки без RViz:

```bash
ros2 launch rtk2026_bringup sim_slam_launch.py \
  robot_model:=tracked \
  use_rviz:=false
```

Управление:

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args \
  -p stamped:=true \
  -p use_sim_time:=true \
  -p frame_id:=base_footprint
```

`teleop_twist_keyboard` сохраняет последнюю заданную скорость. Для остановки
нужно нажать `space` или `k`.

## Интерпретация одометрии

`TrackedVehicle` рассчитывает `/wheel/odom` по заданным скоростям
контактных поверхностей. При повороте скольжением эта одометрия может
завышать изменение курса относительно `/ground_truth/odom`. Это аналог
идеальной энкодерной одометрии, но отдельного топика с физическими encoder
ticks в этой модели нет.

Текущий EKF не использует yaw и угловую скорость из `/wheel/odom`:
он берёт линейную скорость гусениц и `angular_velocity.z` из IMU.
Поэтому для проверки результата поворота нужно сравнивать
`/odometry/filtered` с `/ground_truth/odom`, а не требовать совпадения
ориентации сырой `/wheel/odom`.

Параметры для дальнейшей калибровки находятся в `model.sdf`:

- `mu` и `mu2` — продольное и поперечное сцепление контакта;
- `steering_efficiency` — компенсация потерь при повороте скольжением;
- ограничения скорости и ускорения.

Изменять их следует по отдельности и проверять прямолинейное движение,
поворот на заданный угол и заезд на балки по `/ground_truth/odom`.
