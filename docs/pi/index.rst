Raspberry Pi
=============

Единственная машина, физически подключённая к Arduino: держит serial-порт,
собирает и заливает прошивку, ретранслирует байты по сети. Общая схема
стенда и обзор транспорта - в :doc:`../bench`.

Код лежит в ``pi/``: ``pi/tools/link_server.py`` - ретранслятор,
``pi/docker/`` - образ со сборочным тулчейном и ``avrdude``.

Найти устройство
-----------------

.. code-block:: bash

   ls -l /dev/serial/by-id/

Найденный путь подставляется в секцию ``devices`` файла
``pi/docker/docker-compose.pi.yml``. Путь по идентификатору устройства
не меняется при перезагрузке, в отличие от ``/dev/ttyUSB0``.

Прошить плату
-------------

.. code-block:: bash

   cd ~/RTK2026
   docker compose -f pi/docker/docker-compose.pi.yml run --rm flash

Собирает прошивку и заливает её через avrdude. Каталог сборки
``arduino/build-pi/`` отделён от локального ``arduino/build/``, чтобы кэш
кросс-компиляции под ARM не смешивался с кэшем ноутбука.

Только сборка, без заливки:

.. code-block:: bash

   docker compose -f pi/docker/docker-compose.pi.yml run --rm build

.. note::

   Образ собирается из корня репозитория, а не из ``pi/``: контейнеру нужен
   доступ и к прошивке в ``arduino/``, и к ретранслятору в ``pi/tools/``.

Запустить ретранслятор
-----------------------

.. code-block:: bash

   docker compose -f pi/docker/docker-compose.pi.yml up link

.. important::

   Порт держит только один процесс. Прошивка и ретранслятор одновременно
   не работают: перед ``flash`` остановите ``link``. Оба к тому же
   конкурируют с ``arduino_bridge`` из ``rtk2026_driver`` за то же
   устройство ``/dev/arduino`` - см. :doc:`../driver`.

``link_server.py``
-------------------

Ретранслятор serial-порта в TCP. Ничего не разбирает и не переупаковывает:
не знает ни про кадры, ни про CRC. Поэтому кадрирование и контрольные суммы
работают из конца в конец, от прошивки до инструмента на ноутбуке, и
повреждение по дороге будет замечено кодеком там, а не спрятано
ретранслятором.

Телеметрия рассылается всем подключённым клиентам, поэтому панель состояния
и инструмент настройки на ноутбуке могут работать одновременно. Команды же
принимаются от всех клиентов и сливаются в один поток: два одновременно
командующих инструмента будут мешать друг другу, прошивка исполнит ту
команду, что пришла последней. Сервер это не запрещает - он не может
отличить осмысленную одновременную работу от ошибки оператора, - но считает
число писавших клиентов и печатает его в статистике.
