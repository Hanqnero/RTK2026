Прошивка Arduino Mega
=====================

Каталог ``arduino/`` содержит основную прошивку ATmega2560, два стендовых
варианта, собственную сборку CMake/AVR и Python-инструменты настройки привода.
Код Arduino не является ROS-узлом: граница с ROS проходит по кадрированному
бинарному протоколу версии 2.

Python-инструменты настройки и код ретранслятора для Raspberry Pi лежат
отдельно от прошивки, в ``pc/`` и ``pi/`` - работают и с платой, воткнутой
в ноутбук, и с платой на Raspberry Pi через сетевой ретранслятор. Схема
стенда описана в разделе :doc:`../bench`.

Поток одного цикла
------------------

.. code-block:: text

   readIncomingFrames()
          │
          ├── разбор кадров, проверка CRC
          ├── ограничение linear/angular, отбраковка NaN
          └── обновление last_command_ms
                    │
                    ▼
   applyCommandTimeout()
                    │
                    ▼
   runControlCycle(dt_us) каждые kControlPeriodUs
          ├── снять дельты энкодеров
          ├── вычислить скорости колёс и корпуса по фактическому dt
          ├── проинтегрировать x, y, heading
          ├── проверить сонар и таймаут команды
          ├── левый регулятор:  FF + uPID -> PWM
          ├── правый регулятор: FF + uPID -> PWM
          └── передать TelemetryPayload (+ PidDebugPayload по флагу)
                    │
                    ▼
   maybeSendStats() раз в kStatsPeriodMs

Период ``kControlPeriodMs = 100`` соответствует **10 Гц**. Формулы скорости
и одометрии используют фактический интервал ``dt_us``, измеренный по
``micros()``, а не номинальный период; расхождение между ними видно
в ``profile_firmware.py``.

Ориентация железа
-----------------

Все инверсии моторов и энкодеров живут в одном месте — блоке флагов
``k*Reverse`` в ``motor_interface.h``. Контракт: положительный PWM крутит
колесо вперёд, положительная дельта энкодера означает вращение вперёд.
При его выполнении кинематика, одометрия и телеметрия работают в соглашении
ROS без единой дополнительной инверсии. Проверяется через ``verify_signs.py``.

Актуальные ограничения
----------------------

* ``uPID`` принимает период только в целых миллисекундах, поэтому при
  переходе на 100 Гц разрешения станет не хватать;
* ``pulseIn`` сонара может блокировать цикл до ``kSonarEchoTimeoutUs``;
* нет проверки NaN в расчётах одометрии;
* BMI270 сейчас входит только в отдельную тестовую прошивку, но не в основной
  контур управления.

Закрыто переходом на протокол v2
--------------------------------

* появились sync-слово, длина и CRC: потеря байта больше не сдвигает поток
  навсегда;
* появилось поле ``seq``: потеря пакета отличима от задержки;
* скорость считается по фактическому интервалу, а не по номинальному периоду;
* входящие команды проверяются на NaN в прошивке;
* потери, ошибки CRC, срывы периода и стоимость сонара считаются и
  публикуются в ``StatsPayload``;
* убран ``filterEncoderDeltas``, подменявший дельты энкодеров средним;
* появились независимые регуляторы на каждое колесо с feedforward,
  поэтому моторы настраиваются по отдельности;
* коэффициенты задаются по serial и хранятся в EEPROM, перепрошивка
  для настройки больше не нужна;
* интегралы сбрасываются при таймауте, стопе по сонару, смене знака
  уставки и установке новых коэффициентов.
