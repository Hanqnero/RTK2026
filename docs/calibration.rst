Калибровка привода и одометрии
==============================

Калибровка выполняется в порядке ``знаки → радиус → асимметрия → колея``.
Изменение нескольких коэффициентов одновременно делает результат
неидентифицируемым.

1. Знаки
--------

При положительной команде движения вперёд:

* оба колеса физически вращают робот вперёд;
* обе энкодерные дельты положительные;
* ``/wheel/odom.twist.twist.linear.x`` положителен;
* X в ``odom -> base_footprint`` растёт при начальном yaw=0.

Arduino проверяется ``verify_signs.py`` на поднятом роботе. В Gazebo итоговый
SDF обоих wheel joints должен содержать ``<xyz>0 1 0</xyz>``.

2. Эффективный радиус
---------------------

Выполните несколько прямых проездов на известное расстояние. Для каждого:

.. math::

   m_{r,new}=m_{r,old}\frac{D_{truth}}{D_{odom}}

Если odometry показывает 2.10 м при реальных 2.00 м, новый общий multiplier
равен ``2.00/2.10 = 0.9524``. В симуляции truth берётся из
``/ground_truth/odom``; на реальном роботе — из измеренной траектории.

3. Асимметрия колёс
-------------------

После общего масштаба подайте прямую команду и измерьте систематический уход
по yaw. Ненулевой средний yaw на повторных прямых заездах указывает на разные
эффективные радиусы. Корректируйте ``left_wheel_radius_multiplier`` и
``right_wheel_radius_multiplier`` симметрично малыми шагами, сохраняя средний
масштаб.

4. Эффективная колея
--------------------

Выполните поворот примерно на 90°, чтобы избежать неоднозначности quaternion
после полного оборота. Рассчитайте:

.. math::

   m_{b,new}=m_{b,old}
      \frac{|\Delta\theta_{odom}|}{|\Delta\theta_{truth}|}

Если odometry завышает угол, multiplier увеличивают; если занижает —
уменьшают. Повторите повороты влево/вправо на нескольких скоростях и используйте
медиану.

.. warning::

   Если вычисленный multiplier зависит от скорости или направления сильнее
   нескольких процентов, причиной является контакт, люфт или проскальзывание,
   а не постоянная геометрическая ошибка. Коэффициентом это маскировать нельзя.

Ground truth в Gazebo
---------------------

Мост ``/ground_truth/odom`` поднимается вместе с симуляцией, отдельно
запускать его не нужно. Вручную, если мост почему-то не поднялся:

.. code-block:: bash

   ros2 run ros_gz_bridge parameter_bridge \
     '/ground_truth/odom@nav_msgs/msg/Odometry[gz.msgs.Odometry'

Сравниваются:

* ``/wheel/odom`` — интегрирование wheel joint feedback;
* ``/odometry/filtered`` — результат локального EKF;
* ``/ground_truth/odom`` — фактическая физическая поза модели.

Перед тестом остановите другие publishers ``/cmd_vel``. Конкурирующие teleop и
диагностический publisher делают эксперимент невоспроизводимым.

Оценка серии испытаний
----------------------

Для каждого одинакового манёвра вычислите ошибку
``e = [e_x, e_y, e_yaw]``. Среднее ``mean(e)`` показывает систематическое
смещение, которое исправляют калибровкой. Ковариация показывает разброс после
устранения bias:

.. math::

   C=\frac{1}{N-1}\sum_{k=1}^{N}(e_k-\bar e)(e_k-\bar e)^T

Корреляция нормирует ковариацию:

.. math::

   \rho_{ij}=\frac{C_{ij}}{\sqrt{C_{ii}C_{jj}}}

Сильная связь ``e_y ↔ e_yaw`` обычно означает, что ошибка поворота уводит
траекторию в сторону. Это статистика серии заездов, а не 4×4 TF-матрица из
``tf2_echo`` и не correlation response ``slam_toolbox``.
